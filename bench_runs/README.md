# Bench runs: one report per live Raspberry Pi run

Each `pytest tests/test_bench_link.py --live` run writes its own report to `reports/dev/traceability.md` (a partial run, not for record), and the next run overwrites it. The reports are kept here, one file per run, so the numbers quoted across runs (jitter ranges, worst gaps, flag and recovery times) trace back to the run that measured them.

| Set | Runs | Live monitor | Files |
| --- | --- | --- | --- |
| Test Set 1 | 1 kept (2 were run) | off (not built yet) | `set1-run1.md`, regenerated by replaying the Oct 16 recording (kept in the project's earlier repository); the second Oct 16 run was not kept |
| Test Set 2 | 10 | on | `set2-run01.md` to `set2-run10.md` |
| Test Set 3 | 3 | off (A/B check) | `set3-run1.md` to `set3-run3.md` |
| Test Set 4 | 1 | on | the live run the run for record replays: its numbers are in [reports/traceability.md](../reports/traceability.md) (L1, L2) and `bench_data/` |

Only the run for record's recording is kept in `bench_data/`; the other runs keep their reports here, not their raw recordings.
